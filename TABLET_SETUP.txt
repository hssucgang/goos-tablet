PUTTING THE PRODUCTION APP ON THE TABLET
=======================================

This folder is the whole app.

READ THIS FIRST - IT DECIDES WHICH ROUTE YOU WANT
--------------------------------------------------
Android judges a web app by HOW IT IS OPENED, not by what is in it.

If you copy this folder to the tablet and open index.html directly,
Android treats it as a local document, and it will NOT offer to add it
to the home screen. That is a browser rule, not something this app can
switch on. Opening it that way also silently turns OFF the best part of
the app: writing finished reports STRAIGHT into your OneDrive folder.
It falls back to the share sheet instead.

Serving the same folder over an https link fixes all of that at once.
Nothing inside the app changes - only how it is opened.

                                   opened as a    served over
                                   local file      https
  Runs the batches                  yes            yes
  Add / install to home screen      NO             yes
  Full screen, no address bar       no             yes
  Reports written straight into
    your OneDrive folder            NO             yes
  Reports via the share sheet       yes            yes
  Works with no signal              yes            yes

ROUTE 1 - RECOMMENDED: GitHub Pages (free, permanent, no card)
----------------------------------------------------------------
Done once, on a laptop. Takes about ten minutes the first time and
about one minute for every update afterwards.

FIRST TIME
  1. Make a free account at github.com if you do not have one.
  2. Top right "+" -> New repository.
       Repository name:  goos-tablet
       Visibility:       Public   (see the note below - this is
                         required on a free account)
       Tick "Add a README file".
     Click Create repository.
  3. On the repository page: Add file -> Upload files.
     Open the GOOS_Tablet folder on your laptop, select ALL SIX files
     INSIDE it, and drag them in:
       index.html   manifest.json   sw.js
       icon-192.png   icon-512.png   TABLET_SETUP.txt
     Do NOT drag the folder itself. index.html has to sit at the top
     level of the repository or the link will show a blank page.
     Click Commit changes.
  4. Settings (top of the repository) -> Pages (left sidebar).
       Source: Deploy from a branch
       Branch: main        Folder: / (root)
     Click Save.
  5. Wait a minute or two, then refresh that Pages screen. It will show
     your link:
       https://YOURNAME.github.io/goos-tablet/
  6. On the tablet, open that link in Chrome.
     Chrome menu (three dots) -> "Install app" (or "Add to Home screen").

Done. The tablet now has its own icon, opens full screen with no
address bar, can write reports straight into your OneDrive folder, and
keeps working with no signal.

WHY THE REPOSITORY HAS TO BE PUBLIC
  GitHub only publishes Pages from a public repository on a free
  account. Publishing from a private one needs a paid plan.
  Public means anyone who finds the address can view the app screens -
  the empty shell. It does NOT expose any of your business data:
  recipes, quantities, LOT numbers, customers and finished reports are
  never in these files. The recipes arrive on the tablet as the json
  file the operator picks, and the reports are written back out on the
  tablet. Nothing about your business is uploaded here.
  If you would still rather it not be public at all, Cloudflare Pages
  gives the same result from a private source, also free.

PUSHING AN UPDATE LATER
  1. In GOOS press "Set up tablet app" to refresh this folder.
  2. On GitHub: open the repository -> Add file -> Upload files ->
     drag the changed files in (usually index.html and sw.js) ->
     Commit changes. It re-publishes in about a minute.
  3. On the tablet, open the app WITH SIGNAL once. It notices the new
     version and swaps itself over. If it still looks old, close it
     fully and open it again.
  The tablet deliberately keeps its own copy so it works in the
  commissary with no signal, which is why an update needs one online
  open to land.

ROUTE 2 - straight off the tablet, no accounts, no internet at all
-------------------------------------------------------------------
1. Copy this entire folder onto the tablet (USB cable, or the OneDrive
   app with the folder made available offline).
2. Open index.html with Chrome.
3. Bookmark it. There will be no home-screen icon and no install
   option - see the table above.

The app still runs every batch correctly this way. Finished reports go
out through the share sheet (share to OneDrive, email, or whatever the
tablet has) rather than being written into the folder for you.

WHEN GOOS IS UPDATED - HOW THE TABLET PICKS IT UP
-------------------------------------------------
1. In GOOS press "Set up tablet app".
2. Upload the files from the "App files" folder to GitHub, replacing
   the old ones.
3. On the tablet, open the app WITH SIGNAL. The page itself is fetched
   fresh whenever there is signal, so the new version is there
   immediately - you do not have to close and reopen.
4. Check the version. It is shown on the batch list and in the corner
   of the Cooking screen. If it does not match the version GOOS just
   wrote, the upload has not gone through yet.

If the tablet has NO signal it keeps working from the copy it already
has - that is deliberate, and it is why the version number is on
screen where the work happens.


DAILY USE (either route)
------------------------
1. In GOOS: Schedule Production -> "Send recipes to the tablet". That
   writes ONE file, PROD_TODAY_<production date>.json, into the tablet
   folder - named for the day the work is FOR. Nothing else is written
   there, and the previous day's schedule moves into "Past schedules".
2. On the tablet: just open the app.
   - Served over https on a browser with the folder picker: TWO folders
     are chosen ONCE, on the first morning - the folder GOOS sends
     schedules to, and the folder finished reports go into. They can be
     two different OneDrive folders. The tablet remembers both, and
     "Folders" on the batch list changes them later. After that the app
     finds the newest schedule by itself. Some browsers ask for the
     folder permission again after a restart - that is one tap on the
     single button on screen, and it re-grants both at once.
     If only the schedules folder is chosen, reports go into a
     "Finished Production" subfolder of it, as before.
   - On a browser with no folder picker (Android Chrome today): tap the
     file box and pick PROD_TODAY_<today>.json. It is the only file
     there, so there is nothing to hunt through, and it is once a day.
3. Staff sign in and work through the batches.

SUPERVISOR OVERRIDE (when a recipe changes mid-shift)
-----------------------------------------------------
A locked LOT is never edited - it is VOIDED whole. On the tablet, tap
"Supervisor override" (it is on the batch list and on every batch
screen), choose what to do, write the reason, put your name, and enter
the CEO password. The open batch leaves as a VOID_Prod_<date>_<LOT>
report so what was already weighed stays on the record, and GOOS
refuses to import it as production.

The passcode is checked ON THE TABLET against a verifier GOOS puts
inside the schedule file - it works with no signal, and no passcode is
ever stored on the tablet. Five wrong tries locks the override for
five minutes. Schedules sent by GOOS 2.45 or earlier carry no
verifier: send the schedule again to enable the override.
4. Finished reports come back as Finished_Prod_<production date>_<LOT>
   (.pdf and .csv) inside a "Finished Production" subfolder of the same
   tablet folder, which the app makes by itself. GOOS watches that
   subfolder, and the Raw Materials and QA imports open there.

THE APP FILES ARE NOT IN THE TABLET FOLDER
------------------------------------------
"Set up tablet app" writes index.html, sw.js, manifest.json, the icons
and this file into an "App files" subfolder. Those go to the host; the
tablet folder itself is kept empty except for the day's schedule so
staff cannot pick the wrong thing.

Progress is stored on the tablet itself, so a flat battery or a locked
screen mid-batch loses nothing. Tell staff not to use "clear browsing
data" to fix a problem - that is the one thing that does wipe it.
